# www.xedur.com

Source code for [www.xedur.com](https://www.xedur.com/), the code portfolio of Eetu Rantanen (XeduR). Most projects are Solar2D games and tools that run in the browser as embedded HTML5 builds.

The site is hosted on GitHub Pages and generated by a custom Python static page builder.

## Project structure

```

│   ├── nav.js                  # Navbar scroll and mobile toggle
```

## Building

Run the build script from the `tools/` directory:

```bash
python update_website.py            # incremental build
python update_website.py min        # incremental build, minified HTML
python update_website.py force      # full rebuild, ignoring the skip cache
python update_website.py min force  # full minified rebuild (either arg order)
```

The committed site is built with `min`. A plain run rewrites every page and `js/*.js` unminified.

### What it generates

| Output | Source |
|--------|--------|
| `index.html` | `frontpage.html` template + the category manifests and demo front matter |
| `404.html` | `404.html` template + every valid path, for fuzzy URL matching |
| `sitemap.xml` | Every valid page path, with lastmod dates kept in `tools/components/data/sitemap_dates.json` |
| `llms.txt` | `tools/components/data/llms.json` + the category manifests |
| `demo/index.html` | `demo-index.html` template (a noindex list of all demos) |
| `demo/<folder>/index.html` | `demo.html` template + the demo's `tools/demos/<folder>.md` |
| `demo/<folder>/app/index.html` | `iframe.html` template (Solar2D app loader) |
| `tangents/<slug>/index.html` | `tangents-post.html` template + `tools/tangents/<slug>.md` |
| `tangents/` and `tangents/<n>/` | `tangents-list.html` template (paginated index, 10 per page) |
| `tangents/tag/<slug>/` | `tangents-list.html` template (per tag, paginated) |
| `tangents/feed.xml` | Atom 1.0 feed of the newest posts |
| `tangents/<slug>/<slug>-social.png` | Auto-generated 1200x630 social card (unless `socialImage` names a custom file) |
| `tangents/tangents-social.png` | Generic social card for the index, pagination, and tag pages |
| `js/*.js` | Copied from `tools/js/` (minified with `min`) |

The build never touches `img/`, `fonts/`, or the app binaries inside `demo/` folders; those are managed by hand. CSS lives in `tools/css/styles.css` and is inlined into every page, so there is no root `css/` folder. A sitemap entry gets today's date only when its page's content changed.

### Incremental builds and caching

The builder regenerates only what changed and prunes output that no longer has a source.

- Per-item pages (each demo page, its app loader, each Tangents post, and each copied `js/*.js`) are skipped when none of their sources changed.
- Change detection hashes each source file's bytes rather than reading modification times, so a fresh `git clone` does not force a rebuild.
- Aggregate pages (`index.html`, `demo/index.html`, the Tangents list and tag pages, the feed, `404.html`, `sitemap.xml`, `llms.txt`) are regenerated every run. A byte-identical result is never written, so repeated runs cause no git churn.
- A change to `base.html`, `navbar.html`, `footer.html`, `tools/css/styles.css`, `update_website.py`, or `markdown_engine.py` rebuilds every per-item page, because each of them affects every page.
- Switching between normal and `min` output also rebuilds every page.
- A generated page whose source is gone (a deleted demo `.md`, a dropped manifest entry, a deleted post, a pagination page that no longer exists) is deleted, along with its now-empty directory.
- Pruning only ever deletes paths that match a known generated-output pattern. Any other stale cache entry is logged as a warning and left alone, so a corrupted cache can never remove a manual asset such as `img/`, demo thumbnails, app binaries, or a custom `socialImage` file.
- `force` rebuilds every page regardless of the cache, while pruning and the app-loader listing check keep working.

The cache lives at `tools/.build_cache.json` (gitignored). Deleting it triggers one full rebuild with byte-identical output, and a corrupt cache is treated as absent.

### Build log

Every run writes a report to `tools/build_logs/build_log_<YYYY-MM-DD_HH-MM-SS>.txt` (gitignored): the mode, whether it was forced, the counts of files written, skipped, and pruned, and the lists of errors, warnings, written files, and pruned paths. Only the newest 30 logs are kept.

## Adding and updating projects

Each project is a markdown file at `tools/demos/<stem>.md` whose stem is listed in one of the category manifests: `tools/demos/games.json`, `solar2d.json`, or `other.json`.

A manifest holds:

- `sectionTitle` and `sectionDescription` for the homepage section.
- `sectionIndex`, the two-digit number shown beside the section heading.
- An optional `"band": true`, which puts the section on the alternating full-bleed background.
- `demos`, the ordered list of stems; that order is the display order on the homepage.

The Roso Games and Contact sections are not manifests, so their numbers (02 and 05) and the Roso band live in `frontpage.html` and `contact.html`.

The file stem is the demo identity. For regular and standalone demos it must equal the front-matter `folder` and the `demo/<folder>/` directory. For external links it is any unique kebab-case id.

Front matter is a flat `key: value` block between `---` fences. It cannot nest, so SEO overrides are individual keys rather than an `seo` object.

### Entry types

The build decides the type from the front matter, in this order:

1. Has `externalUrl`: an external link.
2. Has `type: standalone`: a standalone project.
3. Otherwise: a regular demo.

**Regular demo**: a Solar2D HTML5 build that runs in an iframe.

```
---
title: The Dark
folder: the-dark
descriptionShort: Card description shown on the homepage.
tech: Solar2D, Lua
ogTitle: XeduR - The Dark
ogDescription: Description for social media shares.
metaDescription: Custom meta description.
---
The long description in markdown: paragraphs, **bold**, *italic*, `- ` lists, `## ` subheadings, and `[text](url)` links.

**How to play:**

- Controls go here.

[[github url="https://github.com/XeduR/..."]]
```

- The card thumbnail is `demo/<folder>/<folder>-small.jpg` and the `.bin` name is detected from `demo/<folder>/app/`, so neither needs a key.
- `tech`, `ogTitle`, `ogDescription`, `metaDescription`, and `ogImageAlt` are optional.
- A paragraph that is only bold text ending in a colon (`**How to play:**`) renders as a gold label for the content below it.
- The body ends with `[[github url="..."]]` for the public repo panel, or a bare `[[github]]` for the private-source panel.
- Generates `demo/<folder>/index.html` and `demo/<folder>/app/index.html`.

**External link**: a homepage card that opens another site in a new tab. No pages are generated.

```
---
title: Solar2D Playground
externalUrl: https://www.solar2dplayground.com/
image: img/external/solar2d-playground.jpg
descriptionShort: Card description.
tech: HTML5, CSS3, JavaScript
---
```

`image` is required because there is no `folder` to derive a thumbnail from, and there is no body.

**Standalone project**: a custom HTML/JS page in the site's chrome instead of an iframe-loaded app. Only the Pseudorandom Number Generator uses it.

```
---
title: Pseudorandom Number Generator
folder: pseudorandom-number-generator
type: standalone
descriptionShort: Card description.
tech: HTML5, CSS3, JavaScript, Lua
---
```

There is no body: the page comes from `tools/standalone/<folder>/`, and only `demo/<folder>/index.html` is generated.

| File | Required | Purpose |
|------|----------|---------|
| `content.html` | Yes | The page body, inserted into the base template |
| `config.json` | Yes | Page metadata: `title`, `metaDescription`, `metaKeywords`, optional `seo` |
| `head.html` | No | Extra `<head>` tags for the project's own CSS and JS |

### Adding a regular demo

1. Build the Solar2D project for HTML5 and run `html5_build_patcher.py` on the build folder (see below).
2. Put the build files (`.bin`, `.data`, and the rest) in `demo/<folder>/app/`.
3. Add `<folder>-small.jpg` and `<folder>-large.jpg` to `demo/<folder>/`.
4. Create `tools/demos/<folder>.md` and add `<folder>` to the right category manifest.
5. Run the build.

### Adding a standalone project

1. Create `tools/standalone/<folder>/` with `content.html`, `config.json`, and optionally `head.html`.
2. Add `<folder>-small.jpg` and `<folder>-large.jpg` to `demo/<folder>/`, plus any CSS or JS in `demo/<folder>/css/` and `demo/<folder>/js/`, referenced from `head.html` with the `{{basePath}}` prefix.
3. Create `tools/demos/<folder>.md` with `type: standalone` and add `<folder>` to the manifest.
4. Run the build.

### Adding an external link

1. Create `tools/demos/<stem>.md` with `externalUrl` and `image` (usually `img/external/<name>.jpg`), and add `<stem>` to the right category manifest.
2. Run the build.

### Patching HTML5 builds

Run `html5_build_patcher.py` on every new Solar2D HTML5 build before copying it into `demo/<folder>/app/`:

```bash
python html5_build_patcher.py path/to/build/folder
```

It patches the `.bin` and the generated `index.html`:

- Removes the blur callback that freezes the app when the user clicks outside it.
- Removes the `alert()` from `printErr` that pops up on non-fatal WASM errors.
- Deletes the unused `index-debug.html` and `index-nosplash.html`.

### SEO overrides

A regular demo's meta description defaults to `descriptionShort`, and its social tags default to `ogTitle` = `XeduR - <title>`, `ogDescription` = `descriptionShort`, and `ogImageAlt` = `Screenshot of <title>`. Override any of them with front-matter keys:

```
metaDescription: Custom meta description.
ogTitle: Title for social media shares
ogDescription: Description for social media shares
ogImageAlt: Alt text for the preview image
```

`ogImage` is always `demo/<folder>/<folder>-large.jpg`. Keywords fall back to the site-wide defaults.

## Tangents (writing system)

Tangents is the markdown-written writing section at `/tangents/`: paginated list pages, per-tag pages, post pages, and an Atom feed. Posts live in `tools/tangents/<slug>.md`, where the file stem is the slug and the URL is `/tangents/<slug>/`. Slugs are lowercase kebab-case (`[a-z0-9-]`).

### Writing a post

1. Create `tools/tangents/<slug>.md` with front matter and a markdown body.
2. Commit any post images into `tangents/<slug>/` and reference them with `[[image src="foo.png" ...]]`; paths resolve relative to the post URL.
3. Run the build.

Front matter is a flat `key: value` block between `---` fences, with literal trimmed values and no quoting:

| Key | Required | Purpose |
|-----|----------|---------|
| `title` | Yes | Page `<h1>`, `<title>`, list and feed title |
| `summary` | Yes | List blurb, meta description, OG and feed summary |
| `tags` | No | Comma list; drives the tag chips and tag pages |
| `published` | No | `YYYY-MM-DD` to backdate; otherwise set on the first build |
| `draft` | No | `true` leaves the post out of the build entirely |
| `socialImage` | No | Custom social image filename in `tangents/<slug>/`; absent or `auto` generates a card |

### Markdown syntax

Headings (`##` to `######`; a body `#` becomes `##` because the title is the only `<h1>`), paragraphs, `**bold**`, `*italic*` or `_italic_`, `[text](url)`, `` `inline code` ``, `-`/`*` and `1.` lists, `>` blockquotes, `---` rules, and ```` ``` ```` fenced code blocks. Raw HTML is escaped. Nested lists and multi-paragraph list items are not supported.

Directives sit on their own line as `[[name key="value"]]`:

- `[[image src="foo.png" alt="..." caption="..." width="..." height="..."]]`: a `<figure>`, with `src` resolved relative to the post URL.
- `[[youtube id="VIDEO_ID" title="..."]]`: a click-to-load video embed (see below).
- `[[github repo="owner/name"]]`, `[[github url="https://..."]]`, or a bare `[[github]]`: the repository panel.

An unknown or mistyped directive is a build error.

### Dates

Publish dates and body hashes live in `tools/components/data/tangents_dates.json`, which is committed because publish dates cannot be re-derived. A post is published on its first build, or on its `published` date. "Last updated" changes only when the rendered body changes, so editing `summary`, `tags`, or `title` alone does not bump it. Dates render as `13 July 2026`.

### Pagination, tags, feed

List pages hold 10 posts, newest first (`/tangents/`, `/tangents/2/`, and so on). Each tag gets its own paginated set at `/tangents/tag/<slug>/`. Two tag spellings that slugify to the same value (`Solar2D` and `solar2d`) are a build error. The feed at `/tangents/feed.xml` carries the newest 20 posts and is linked from every post.

### YouTube consent

`[[youtube]]` renders a thumbnail placeholder, not an iframe. `js/video-consent.js`, loaded only on pages that need it, swaps in a `youtube-nocookie.com` iframe after the visitor clicks "I accept". Consent is stored in `localStorage` (`videosAccepted`), so the site sets no cookie and requests nothing from `youtube-nocookie.com` before consent. The thumbnail itself comes from `img.youtube.com` before consent.

### Social share images

Every post page gets a branded 1200x630 card (the X mark, a "Tangents" label, and the post title) at `tangents/<slug>/<slug>-social.png`. One generic card at `tangents/tangents-social.png` serves the index, pagination, and tag pages.

The `socialImage` key overrides the default:

- Absent or `auto`: generate the card.
- `<filename>`: use the committed `tangents/<slug>/<filename>` as is; 1200x630 is recommended. A missing file warns and falls back to the generated card.
- `<slug>-social.png`, the generated name, is a build error.

Generated cards are committed. A card regenerates only when the generator script, the post title, or the logo and font assets change, tracked in `tools/components/data/social_images.json`. Deleting a post prunes its generated card; a custom `socialImage` file is never pruned.

Rendering needs [Pillow](https://python-pillow.github.io/), which is imported only when a card actually renders, so an up-to-date build never loads it. A needed render without Pillow fails the build with a clear message. Card text uses the Roboto files in `tools/components/fonts/`.

The generator also runs on its own while iterating on the card design:

```bash
python generate_social_images.py              # every non-draft post + the generic card
python generate_social_images.py force        # regenerate everything (writes only what changed)
python generate_social_images.py <slug> ...   # only the named posts
```

It refreshes the images and the manifest only; run `update_website.py` for the pages.

## Templates

HTML templates live in `tools/components/templates/` and use `{{placeholder}}` tokens that the build replaces. `{{basePath}}` holds the relative path back to the site root (`./` on the homepage, `../../` on demo pages).

| Template | Purpose |
|----------|---------|
| `base.html` | Root HTML document (head, meta tags, favicons, font preloads, navbar, footer) |
| `navbar.html` | Navigation bar (desktop and mobile) |
| `footer.html` | Page footer |
| `frontpage.html` | Homepage layout (intro, sections, Roso Games, contact) |
| `section.html` | Homepage section with numbered heading, description, and card grid |
| `card.html` | Project card |
| `contact.html` | Contact section at the bottom of the homepage |
| `demo.html` | Demo page (rendered markdown body and the app embed) |
| `demo-index.html` | List of all demos at `demo/` |
| `iframe.html` | Solar2D HTML5 app loader with Zlib decompression and progress bar |
| `repo-panel.html` | Public repository panel (from the `[[github]]` directive) |
| `repo-panel-private.html` | Private-source panel (from a bare `[[github]]`) |
| `tangents-post.html` | Tangents post page |
| `tangents-list.html` | Tangents index and tag pages |
| `tangents-item.html` | One row in a Tangents list |
| `404.html` | Error page with the valid paths for fuzzy URL matching |
